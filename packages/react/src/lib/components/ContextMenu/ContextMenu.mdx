# ContextMenu Component

The `<ContextMenu>` component is a radial (pie-style) context menu - a ring of segments arranged
around a center point, each showing an icon and dispatching an action when clicked. It's pluggable:
every icon, label and click handler is provided by the caller, so the same component can show a
completely different set of actions depending on what it was opened on.

<Canvas of={ContextMenuStories.Background} />

## Usage

`<ContextMenu>` itself is a small, controlled component - it doesn't know how it was triggered, or
what it's connected to. It's a thin React wrapper around `renderContextMenu`, a framework-agnostic
D3 module exported from `@chart-io/core` that owns the actual rendering/animation/interaction, so
the same implementation can back a rendering layer for any framework (e.g. `@chart-io/svelte` could
call `renderContextMenu` directly) rather than being reimplemented per-framework:

```jsx
<ContextMenu
    x={120}
    y={80}
    open={isOpen}
    items={items}
    onSelect={(item) => {
        item.onSelect(dispatch, context);
        close();
    }}
    onClose={close}
/>
```

Its open/closed state, position and context (e.g. which datum it was opened on) live under
`eventSelectors.contextMenu` in the Redux store - the same convention the mouse position/tooltip/
droplines/markers already use - opened and closed via `eventActions.openContextMenu`/
`closeContextMenu`. `<ContextMenuOverlay>` does exactly this, and is the version to reach for first;
see below for wiring up a menu on a specific datum the same way.

### `<ContextMenu>` Props

| Prop                | Type                                | Default            | Note                                                                                     |
| ------------------- | ------------------------------------ | ------------------- | ----------------------------------------------------------------------------------------- |
| **`x`\***           | `number`                            |                     | The x-coordinate to anchor the menu at                                                    |
| **`y`\***           | `number`                            |                     | The y-coordinate to anchor the menu at                                                    |
| **`open`\***        | `boolean`                           |                     | Whether the menu should be shown. Segments animate in/out as this changes                 |
| **`items`\***       | `IContextMenuItem[]`                |                     | The pluggable set of actions to show as segments, clockwise from 12 o'clock               |
| `radius`            | `number`                            | 28                  | The inner radius of the ring, in pixels                                                   |
| `thickness`         | `number`                            | 46                  | The depth of each segment, in pixels                                                      |
| `padAngle`          | `number`                            | 0.025               | The angular gap, in radians, between segments                                             |
| `iconSize`          | `number`                            | 18                  | The size, in pixels, each item's icon is scaled to                                        |
| `animationDuration` | `number`                            | 220                 | How long, in milliseconds, the show/hide animation takes                                  |
| `colors`            | `ITheme["menu"]`                    | `themes.light.menu` | The color palette to render the menu with                                                 |
| **`onSelect`\***    | `(item: IContextMenuItem) => void`  |                     | Called when an enabled item is clicked                                                    |
| `onClose`           | `() => void`                        |                     | Called when the menu should close without a selection - Escape, or clicking outside it    |

### `IContextMenuItem` Schema

`IContextMenuItem` (along with the action factories and icon set below) is exported from
`@chart-io/core`, not `@chart-io/react` - it's framework-agnostic, used by `renderContextMenu`
directly.

| Prop         | Type                                                              | Note                                                                                    |
| ------------ | ------------------------------------------------------------------ | ---------------------------------------------------------------------------------------- |
| **`id`\***   | `string`                                                          | A unique identifier                                                                       |
| **`label`\***| `string`                                                          | Shown in a tooltip on hover, and used for accessibility                                  |
| **`icon`\*** | `string`                                                          | Raw SVG markup (e.g. `<path d="..."/>`), sized automatically to fit. See `contextMenuIcons` for a ready-made set |
| `disabled`   | `boolean`                                                         | Renders the segment disabled rather than removing it, so the ring doesn't reflow         |
| **`onSelect`\*** | `(dispatch: IDispatch, context?: IContextMenuContext) => void`| Called when this item is selected                                                        |

## Disabled Items

Rather than removing an item that isn't currently applicable (which would reflow the rest of the
ring), mark it `disabled` - it's still shown, greyed out, and can't be clicked.

# ContextMenuOverlay Component

`<ContextMenuOverlay>` wires a `<ContextMenu>` up to a chart: right-clicking anywhere inside it -
background or on top of a plot - opens the menu, themed to match the chart, and dispatches whichever
action is selected into the Redux store. Add it as a child of `<Chart>`/`<XYChart>`/`<RadialChart>`
alongside your plots:

```jsx
<XYChart data={data}>
    <YAxis fields={["category"]} scaleType="band" />
    <XAxis fields={["value"]} />
    <Bar x="value" y="category" />
    <ContextMenuOverlay />
</XYChart>
```

<Canvas of={ContextMenuOverlayStories.OnChartBackground} />

By default it shows four stubbed-out background actions - override `getItems` to add, remove or
replace any of them:

| Action                | Behaviour                                                                                   |
| ---------------------- | --------------------------------------------------------------------------------------------- |
| **Reset zoom**          | Fully wired up - clears a zoomable plot's zoom path and any `<ZoomBrush>` domain. Disabled while nothing is zoomed in |
| **Hide legend**/**Show legend** | Fully wired up via `chartActions.setLegendVisible`                                    |
| **Pivot**              | A stub - there's no store concept of a heatmap pivot yet                                      |
| **Draw polygon**       | A stub - there's no interactive drawing mode yet                                              |

```jsx
import { createResetZoomAction, createToggleLegendAction } from "@chart-io/core";

<ContextMenuOverlay getItems={(state) => [createResetZoomAction(state), createToggleLegendAction(state)]} />
```

### `<ContextMenuOverlay>` Props

| Prop                | Type                                     | Default                     | Note                                                              |
| -------------------- | ----------------------------------------- | ---------------------------- | -------------------------------------------------------------------- |
| `getItems`           | `(state: IState) => IContextMenuItem[]`  | `getDefaultBackgroundItems`  | Builds the items to show, given the current Redux state              |
| `radius`             | `number`                                 |                              | See `<ContextMenu>`                                                  |
| `thickness`          | `number`                                 |                              | See `<ContextMenu>`                                                  |
| `padAngle`           | `number`                                 |                              | See `<ContextMenu>`                                                  |
| `iconSize`           | `number`                                 |                              | See `<ContextMenu>`                                                  |
| `animationDuration`  | `number`                                 |                              | See `<ContextMenu>`                                                  |

## Menus on a Data Point

`<ContextMenuOverlay>` only covers the chart background. For a menu on a specific datum - "Hide data
point", "Focus data point", "Add annotation" - dispatch `eventActions.openContextMenu` yourself from
a plot's existing `onClick` prop (the same extension point already used for tooltips), and read it
back with a small connected component the same way `<ContextMenuOverlay>` does:

```jsx
function DatumMenu() {
    const dispatch = useDispatch();
    const isOpen = useSelector((s) => eventSelectors.contextMenu.isOpen(s));
    const position = useSelector((s) => eventSelectors.contextMenu.position(s));
    const context = useSelector((s) => eventSelectors.contextMenu.context(s));
    const close = () => dispatch(eventActions.closeContextMenu());

    return (
        <ContextMenu
            x={position?.x ?? 0}
            y={position?.y ?? 0}
            open={isOpen}
            items={getDefaultDatumItems()}
            onSelect={(item) => {
                item.onSelect(dispatch, context);
                close();
            }}
            onClose={close}
        />
    );
}

// The click handler that opens it needs the store before <XYChart> has rendered it into context -
// grab it via onStoreCreated (a plot's own click handler inside the chart would normally just have
// dispatch already in scope some other way)
const onBarClick = (datum, element, event) => {
    const svg = element.closest("svg");
    const point = getSvgPoint(svg, event.clientX, event.clientY);
    store.dispatch(eventActions.openContextMenu({ ...point, context: { type: "datum", datum } }));
};

<XYChart data={data} onClick={onBarClick} onStoreCreated={(createdStore) => { store = createdStore; }}>
    <Bar x="value" y="category" />
    <DatumMenu />
</XYChart>
```

<Canvas of={ContextMenuOverlayStories.OnADataPoint} />

None of "Hide data point", "Focus data point" or "Add annotation" are wired up to real behaviour yet
- there's no store concept of a hidden/excluded/focused/annotated datum. Each stub logs to the
console describing what it would do - replace `onSelect` with a real dispatch once that store state
exists.
