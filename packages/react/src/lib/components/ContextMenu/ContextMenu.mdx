# ContextMenu Component

The `<ContextMenu>` component is a radial (pie-style) context menu - a ring of segments arranged
around a center point, each showing an icon and dispatching an action when clicked. It's pluggable:
every icon, label and click handler is provided by the caller, so the same component can show a
completely different set of actions depending on what it was opened on.

<Canvas of={ContextMenuStories.Background} />

## Usage

`<ContextMenu>` itself is a small, controlled component - it doesn't know how it was triggered, or
what it's connected to. It's a thin React wrapper around `renderContextMenu`, a framework-agnostic
D3 module exported from `@chart-io/core` that owns the actual rendering/animation/interaction, so
the same implementation can back a rendering layer for any framework (e.g. `@chart-io/svelte` could
call `renderContextMenu` directly) rather than being reimplemented per-framework.

It's rendered via a portal straight into `document.body`, positioned with `position: fixed` at
`(x, y)` - so it isn't clipped by a chart's own bounds/`overflow`, and `x`/`y` can be a plain
`MouseEvent`'s `clientX`/`clientY` directly, with no coordinate-space conversion needed:

```jsx
<ContextMenu
    x={120}
    y={80}
    open={isOpen}
    items={items}
    onSelect={(item) => {
        item.onSelect(dispatch, context);
        close();
    }}
    onClose={close}
/>
```

Its open/closed state, position and context (e.g. which datum it was opened on) live under
`eventSelectors.contextMenu` in the Redux store - the same convention the mouse position/tooltip/
droplines/markers already use - opened and closed via `eventActions.openContextMenu`/
`closeContextMenu`. `<ContextMenuOverlay>` does exactly this, and is the version to reach for first;
see below for wiring up a menu on a specific datum the same way.

### `<ContextMenu>` Props

| Prop                | Type                                | Default            | Note                                                                                     |
| ------------------- | ------------------------------------ | ------------------- | ----------------------------------------------------------------------------------------- |
| **`x`\***           | `number`                            |                     | The x-coordinate (viewport/client space) to center the menu at                            |
| **`y`\***           | `number`                            |                     | The y-coordinate (viewport/client space) to center the menu at                            |
| **`open`\***        | `boolean`                           |                     | Whether the menu should be shown. Segments animate in/out as this changes                 |
| **`items`\***       | `IContextMenuItem[]`                |                     | The pluggable set of actions to show as segments, clockwise starting just past the bottom gap |
| `radius`            | `number`                            | 18.9                | The inner radius of the ring, in pixels                                                   |
| `thickness`         | `number`                            | 31.05               | The depth of each segment, in pixels                                                      |
| `padAngle`          | `number`                            | 0.025               | The angular gap, in radians, between segments                                             |
| `gapAngle`          | `number`                            | `Math.PI / 4`       | The angular gap, in radians, left at the bottom (6 o'clock) - a thumb-sized notch          |
| `iconSize`          | `number`                            | 18                  | The size, in pixels, each item's icon is scaled to                                        |
| `animationDuration` | `number`                            | 220                 | How long, in milliseconds, the show/hide animation takes                                  |
| `colors`            | `ITheme["menu"]`                    | `themes.light.menu` | The color palette to render the menu with                                                 |
| **`onSelect`\***    | `(item: IContextMenuItem) => void`  |                     | Called when an enabled item is clicked                                                    |
| `onClose`           | `() => void`                        |                     | Called when the menu should close without a selection - Escape, or clicking outside it    |

### `IContextMenuItem` Schema

`IContextMenuItem` (along with the action factories and icon set below) is exported from
`@chart-io/core`, not `@chart-io/react` - it's framework-agnostic, used by `renderContextMenu`
directly.

| Prop         | Type                                                              | Note                                                                                    |
| ------------ | ------------------------------------------------------------------ | ---------------------------------------------------------------------------------------- |
| **`id`\***   | `string`                                                          | A unique identifier                                                                       |
| **`label`\***| `string`                                                          | Shown in a tooltip on hover, and used for accessibility                                  |
| **`icon`\*** | `string`                                                          | Raw SVG markup (e.g. `<path d="..."/>`), sized automatically to fit. See `contextMenuIcons` for a ready-made set |
| `disabled`   | `boolean`                                                         | Renders the segment disabled rather than removing it, so the ring doesn't reflow         |
| **`onSelect`\*** | `(dispatch: IDispatch, context?: IContextMenuContext) => void`| Called when this item is selected                                                        |

## Disabled Items

Rather than removing an item that isn't currently applicable (which would reflow the rest of the
ring), mark it `disabled` - it's still shown, greyed out, and can't be clicked.

# ContextMenuOverlay Component

`<ContextMenuOverlay>` wires a `<ContextMenu>` up to a chart: right-clicking its background - not a
plot mark, an axis brush, or any other interactive element sitting on top of it - opens the menu
(suppressing the browser's native context menu for just that click), themed to match the chart, and
dispatches whichever action is selected into the Redux store. `<XYChart>`/`<RadialChart>` already
enable it by default (see their `contextMenu` prop) - you don't normally need to add it yourself:

```jsx
<XYChart data={data}>
    <YAxis fields={["category"]} scaleType="band" />
    <XAxis fields={["value"]} />
    <Bar x="value" y="category" />
</XYChart>
```

<Canvas of={ContextMenuOverlayStories.OnChartBackground} />

Pass `contextMenu={false}` to turn it off - e.g. if you want to configure it yourself with a custom
`getItems`, by adding your own `<ContextMenuOverlay>` as a child instead:

```jsx
<XYChart data={data} contextMenu={false}>
    <Bar x="value" y="category" />
    <ContextMenuOverlay getItems={(state) => [createResetZoomAction(state)]} />
</XYChart>
```

By default it shows five stubbed-out background actions - override `getItems` to add, remove or
replace any of them:

| Action                | Behaviour                                                                                   |
| ---------------------- | --------------------------------------------------------------------------------------------- |
| **Reset zoom**          | Fully wired up - clears a zoomable plot's zoom path and any `<ZoomBrush>` domain. Disabled while nothing is zoomed in |
| **Reset filters**      | Fully wired up - clears any `<ParallelCoordinates>` axis brush and any datum hidden via "Hide data point" below. Disabled while neither is set |
| **Hide legend**/**Show legend** | Fully wired up via `chartActions.setLegendVisible`                                    |
| **Pivot**              | A stub - there's no store concept of a heatmap pivot yet                                      |
| **Draw polygon**       | A stub - there's no interactive drawing mode yet                                              |

```jsx
import { createResetZoomAction, createToggleLegendAction } from "@chart-io/core";

<ContextMenuOverlay getItems={(state) => [createResetZoomAction(state), createToggleLegendAction(state)]} />
```

### `<ContextMenuOverlay>` Props

| Prop                | Type                                                          | Default            | Note                                                              |
| -------------------- | ---------------------------------------------------------------- | -------------------- | -------------------------------------------------------------------- |
| `getItems`           | `(state: IState, context?: IContextMenuContext) => IContextMenuItem[]` | `getDefaultItems`  | Builds the items to show, given the current Redux state and the context (background or datum) the menu was opened with |
| `radius`             | `number`                                                          |                      | See `<ContextMenu>`                                                  |
| `thickness`          | `number`                                                          |                      | See `<ContextMenu>`                                                  |
| `padAngle`           | `number`                                                          |                      | See `<ContextMenu>`                                                  |
| `iconSize`           | `number`                                                          |                      | See `<ContextMenu>`                                                  |
| `animationDuration`  | `number`                                                          |                      | See `<ContextMenu>`                                                  |

## Menus on a Data Point

Right-clicking a mark on `<Scatter>`, `<Bar>`/`<GroupedBar>`/`<StackedBar>`, `<Column>`/
`<GroupedColumn>`/`<StackedColumn>`, `<Pie>`/`<Donut>`, `<Line>`/`<Area>`/`<StackedArea>`, `<Radar>`,
`<RadialArea>`, `<Treemap>`, `<CirclePacking>`, `<WordCloud>` and `<Funnel>` already opens the same
`<ContextMenuOverlay>` with `getDefaultDatumItems` - "Hide data point" (fully wired up, via
`chartActions.hideDataPoint`), and stubbed "Focus data point"/"Add annotation" - nothing to set up.
`<ParallelCoordinates>` is the one built-in exception, since its own brush-based filtering already
covers this. `<XYChart>`/`<RadialChart>` still need `contextMenu` left at its default (`true`) for
this to show, the same as the background menu.

For a custom plot without this built in, wire it up the same way those do: call `useDatumContextMenu`
and attach the handler it returns to your mark's own `contextmenu` event:

```jsx
import { useDatumContextMenu } from "@chart-io/react";

function MyPlot({ data }) {
    const onDatumContextMenu = useDatumContextMenu();

    // Inside your D3 join:
    // .on("contextmenu", (event, datum) => onDatumContextMenu(datum, event))
}
```

That dispatches `eventActions.openContextMenu` with a `"datum"` context for you, suppressing the
browser's native menu and stopping the event bubbling up to the background menu's own listener. To
build the menu by hand instead - e.g. to show it somewhere other than `<ContextMenuOverlay>` - read
`eventSelectors.contextMenu` back with a small connected component the same way
`<ContextMenuOverlay>` does:

```jsx
function DatumMenu() {
    const dispatch = useDispatch();
    const isOpen = useSelector((s) => eventSelectors.contextMenu.isOpen(s));
    const position = useSelector((s) => eventSelectors.contextMenu.position(s));
    const context = useSelector((s) => eventSelectors.contextMenu.context(s));
    const close = () => dispatch(eventActions.closeContextMenu());

    return (
        <ContextMenu
            x={position?.x ?? 0}
            y={position?.y ?? 0}
            open={isOpen}
            items={getDefaultDatumItems()}
            onSelect={(item) => {
                item.onSelect(dispatch, context);
                close();
            }}
            onClose={close}
        />
    );
}

// contextMenu={false} turns off the chart's own default <ContextMenuOverlay>, since <DatumMenu>
// above is standing in for it here
<XYChart data={data} contextMenu={false}>
    <MyPlot />
    <DatumMenu />
</XYChart>
```

<Canvas of={ContextMenuOverlayStories.OnADataPoint} />

"Hide data point" is fully wired up, via `chartActions.hideDataPoint` - see `chartSelectors.data`,
which every plot reads its rows through, so a hidden datum disappears from the chart entirely rather
than just fading like a `<ParallelCoordinates>` brush selection does. "Focus data point" and "Add
annotation" remain stubs - there's no store concept of a focused/annotated datum yet. Each logs to the
console describing what it would do - replace `onSelect` with a real dispatch once that store state
exists.
