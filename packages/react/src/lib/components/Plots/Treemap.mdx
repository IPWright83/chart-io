# Treemap Plots

The `<Treemap>` component subdivides the plot area into nested rectangles from a flat dataset:
`categories` is an ordered list of fields, outermost group first. Each level subdivides its parent's
rectangle, with every leaf cell's area proportional to its value. It's a self-contained chart - unlike
`<Bar>`/`<Line>` (which need an `<XYChart>` wrapper) or `<Pie>`/`<Radar>` (which need a `<RadialChart>`
wrapper), `<Treemap>` accepts chart-level props like `data`/`width`/`height` directly, since it only
ever has a single plot.

## `<Treemap>` Component

### Props

| Prop            | Type       | Default             | Note                                                                                                          |
| --------------- | ---------- | -------------------- | -------------------------------------------------------------------------------------------------------------- |
| **`categories`\*** | `string[]` | `null`             | The ordered list of fields to build each level from, outermost group first.                                    |
| **`value`\***   | `string`   | `null`               | The key of the field that contains the size for each cell.                                                     |
| `padding`       | `number`   | `2`                  | The gap, in pixels, to leave between cells, at every level of the hierarchy.                                    |
| `cornerRadius`  | `number`   | `0`                  | The corner radius, in pixels, to apply to each cell.                                                            |
| `sort`          | `boolean`  | `false`               | Should the cells be sorted by value (descending), rather than using the order of the data?                      |
| `colors`        | `string[]` | Derived from Theme   | Override the colours used for each top-level category. Deeper cells inherit their parent's colour.             |
| `interactive`   | `boolean`  | `true`                | Whether the plot should be interactive. Setting this to false will disable tooltips from this plot             |
| `showInLegend`  | `boolean`  | `true`                | Whether the plot should feature in the legend or not. Only the top-level categories appear in the legend.       |
| `buildHierarchy`| `function` | `buildHierarchy` from `@chart-io/core` | Builds the hierarchy from the flat dataset. Override this if your data doesn't fit the flat, group-by-`categories` shape - see below. |

`<Treemap>` also accepts the usual chart-level props - `data`, `width`, `height`, `plotMargin`,
`theme`, `animationDuration`, `onClick`/`onMouseOver`/`onMouseOut` and so on - directly, since it's a
self-contained chart.

> **Note**: Every combination of the fields listed in `categories` should be unique in the data. If your
> data has multiple rows for the same combination, aggregate it first.

Only the deepest level of the hierarchy is drawn as a cell - the nesting of the levels above it is
still visible from the grouping and padding, without needing separate rectangles drawn for each group.

### Using Canvas

Like other plots, a `<Treemap>` can be rendered using an HTML Canvas instead of SVG by setting `useCanvas`.

<Canvas of={TreemapStories.Canvas} />

### N-level hierarchies

`categories` isn't limited to two levels - pass as many fields as your data has levels of hierarchy to
build further nesting. For example `categories={["continent", "country", "sector"]}` produces a 3-level
treemap.

<Canvas of={TreemapStories.ThreeLevel} />

There's no fixed limit on the number of levels - `categories` accepts any number of fields.

<Canvas of={TreemapStories.DeepTreemap} />

### Zooming

Since only leaf cells are drawn, a group never has a cell of its own to click on - so set `zoomable` to
let a click on any cell zoom in and refocus on that cell's immediate parent group instead, expanding it
to fill the available space. Clicking a cell whose parent is already the focused group zooms back out
one level. Add `breadcrumb` to also show the current zoom path as a clickable trail:

<Canvas of={TreemapStories.Zoomable} />

```jsx
<Treemap
    categories={["continent", "country", "sector"]}
    value="gdp"
    zoomable={true}
    breadcrumb={true}
/>
```

### Negative values

None of the fields in `categories` can be negatively sized - a rectangle's area can't represent a
negative value. If the dataset contains negative values in the `value` field, they're treated as `0`
and a `W009` warning is logged - see [the `<StackedDonut>` docs](/docs/radialcharts-stackeddonut--docs)
for the same behaviour on the polar equivalent of this chart.

### Custom hierarchy building

By default `<Treemap>` builds its hierarchy by grouping the flat dataset by each field in `categories`
in turn, summing `value` at every level - the same shared `buildHierarchy` used by `<StackedDonut>`. If
your data doesn't fit that shape - it's already nested, or needs some custom aggregation - pass your own
`buildHierarchy` function instead, matching the signature of the one exported from `@chart-io/core`:

```jsx
import { buildHierarchy } from "@chart-io/core";

<Treemap
    categories={["region", "product"]}
    value="sales"
    buildHierarchy={(data, categories, value, sort, componentName) => {
        // Delegate to the default implementation, or build a d3.hierarchy some other way entirely
        return buildHierarchy(data, categories, value, sort, componentName);
    }}
/>
```
